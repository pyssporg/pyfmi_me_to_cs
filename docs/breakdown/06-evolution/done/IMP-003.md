## Evidence

- `src/cs_fmu_packager/codegen/cmake.py` line 41: `set(FMI_HEADERS_DIR "${CMAKE_CURRENT_SOURCE_DIR}/c_headers")`
- `src/cs_fmu_packager/codegen/cmake.py` line 42: `set(WRAPPER_HEADERS_DIR "${CMAKE_CURRENT_SOURCE_DIR}/src/cs_fmu_packager/codegen")`

## Current Pain Or Risk

Line 42 references `src/cs_fmu_packager/codegen` as a path relative to `CMAKE_CURRENT_SOURCE_DIR`, which is the temporary build directory created by `cli.py` line 153 (`tempfile.TemporaryDirectory`). The `.h` codegen headers are not copied into that temp directory — only the `.c` source files generated by `generate_all()` land there. This means `WRAPPER_HEADERS_DIR` resolves to a non-existent path (`<tmpdir>/src/cs_fmu_packager/codegen`) during actual builds. The header path works only when the build directory happens to be inside the source tree (e.g., manual testing from the project root).

Additionally, `FMI_HEADERS_DIR` at line 41 assumes `c_headers/` exists relative to the build directory, which is also false for temp directory builds unless those headers are copied.

## Proposed Improvement

Copy the `.h` codegen headers (from `src/cs_fmu_packager/codegen/`) to the build directory alongside the generated `.c` files, and copy or symlink the `c_headers/` directory into the build directory. Alternatively, restructure `cmake.py` to use relative source paths and pass the actual header locations as CMake variables via `-D` flags instead of baking relative paths into the generated CMakeLists.txt.

## Expected Benefit

Builds succeed regardless of whether the working directory is the source tree or a temp directory. The generated CMakeLists.txt becomes self-contained with respect to the build context.

## Risk And Blast Radius

Medium. Changes affect `src/cs_fmu_packager/codegen/cmake.py`, `src/cs_fmu_packager/codegen/wrapper.py` (which orchestrates file generation), and possibly `cli.py`. Existing builds may break if the header copy logic has a bug. The blast radius is limited to the code generation and build pipeline.

## Task Contract Seed

In `generate_all()` (wrapper.py), add file copy operations for: (1) all `.h` files from `src/cs_fmu_packager/codegen/` into the output build directory, (2) all `.h` files from `c_headers/` into a `c_headers/` subdirectory of the output build directory. Update `cmake.py` to reference `WRAPPER_HEADERS_DIR` and `FMI_HEADERS_DIR` relative to `CMAKE_CURRENT_SOURCE_DIR` in the generated CMakeLists.txt. Verify with a temp-directory build that header files are resolvable.
