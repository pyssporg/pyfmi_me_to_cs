## Theme

Code consolidation, DRY refactoring

## Evidence

- `src/cs_fmu_packager/codegen/fmi_interface.py` — `_count_type()` is called 12 times with identical patterns for each type×role combination
- Each call follows the same structure: call `_count_type()` with a specific variable filter, collect the result

## Current Pain Or Risk

- ~24 lines of repeated call sites, each nearly identical
- Pattern duplication makes it harder to see the overall counting logic at a glance

## Proposed Improvement

Replace the 12 individual `_count_type()` calls with a dict comprehension or a multi-type counter that iterates over the type×role combinations and populates the counts in a single pass.

## Expected Benefit

- Reduces ~24 lines of repeated calls to a compact data-driven pattern
- Improves maintainability — adding a new type×role combination for counting requires adding one entry to the data structure rather than copying the call pattern

## Risk And Blast Radius

Low. Similar consolidation opportunity to C6 (IMP-020). The generated C output must remain byte-identical. Verify with existing codegen tests.
