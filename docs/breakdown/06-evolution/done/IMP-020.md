## Theme

## Evidence

- `src/cs_fmu_packager/codegen/fmi_interface.py` lines 214–284 — `_variable_mapping_init_code()` is called 12 times with identical structural patterns for each type×role combination
- Each call site differs only in the `varname` string and the filtered variable list passed to it

## Current Pain Or Risk

- ~70 lines of nearly identical call sites, each repeating the same structural pattern
- Adding a new type×role combination requires copying the pattern again, amplifying the duplication
- Understanding the codegen flow requires reading all 12 blocks to confirm they are structurally identical

## Proposed Improvement

Replace the 12 explicit call sites with a single loop over type×role combinations. The loop iterates over a data structure (list of tuples or dict) that maps each combination to its `varname` string and variable filter, calling `_variable_mapping_init_code()` once per iteration.

## Expected Benefit

- Reduces ~70 lines of repeated call sites to a compact loop
- Adding a new type×role combination becomes a single entry in the data structure
- Improves readability — the pattern is explicit once, not repeated 12 times

## Risk And Blast Radius

Low. The generated C output must remain byte-identical. The refactoring changes Python control flow but not the arguments passed to `_variable_mapping_init_code()`. Verify with existing codegen tests that compare generated C output against known-good snapshots.
