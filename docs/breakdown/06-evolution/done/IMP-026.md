# IMP-026: Merge simple fixture/helper code patterns across test files

Use this template for one backlog-ready improvement candidate.

An improvement candidate is not implementation approval. It needs a scoped task contract before code or documentation changes begin.

## Lifecycle Stage

Candidate

## Status

Proposed

## Layer

Evolution

## Theme

Test infrastructure consolidation, DRY refactoring

## Evidence

- Multiple test files in `tests/` duplicate setup patterns:
  - Temp-directory creation (`pytest tmp_path` or manual `tempfile.TemporaryDirectory`)
  - Spec dictionary construction (creating the same `MappingSpec`, `FmuSpec`, variable mapping structures)
  - Common mock FMU creation patterns
- `tests/conftest.py` — exists but may not cover all shared setup patterns

## Current Pain Or Risk

- Setup logic duplicated across test files: if a helper pattern changes (e.g., spec dict field added), all duplicating test files must be updated
- Inconsistent setup creates subtle differences in what each test actually tests
- New test authors must copy-paste setup code rather than calling a shared helper

## Proposed Improvement

Extend `conftest.py` with shared helper functions and fixtures for:
1. Temp-directory management for test FMU output
2. Common spec construction (minimal valid spec, multi-FMU spec, edge-case specs)
3. FMU fixture setup that wraps `_create_minimal_me_fmu()` or similar patterns

## Expected Benefit

- Less duplication across test files
- Consistent setup patterns across all tests
- Easier to change common setup logic in one place
- Lower barrier for new test authors

## Risk And Blast Radius

**Low to moderate.**
- Over-abstraction of test helpers can make tests harder to read (PAT-001 — "tests should be readable as specifications")
- If shared helpers become too flexible, individual tests may become opaque
- Risk is mitigated by keeping helpers surgical: extract only clearly duplicated patterns, do not create a general-purpose test framework

## Task Contract Seed

1. [ ] Survey all test files in `tests/` and catalog duplicated setup patterns
2. [ ] For each pattern present in 3+ files, extract a helper function or fixture to `conftest.py`
3. [ ] Update consuming test files to use the shared helper
4. [ ] Verify no test behavior changes by comparing test counts, coverage, and pass/fail results before and after
5. [ ] Document each shared helper with a docstring describing its contract

## Out Of Scope

- Creating a general-purpose test framework or test utilities package
- Extracting patterns present in fewer than 3 files (not worth the abstraction for single-use patterns)
- Introducing new test dependencies (e.g., `pytest-cases`, `factory_boy`)
- Reorganizing the test file structure

## Traceability

- Intent: Consolidate duplicated test setup patterns into shared helpers
- Product: `tests/conftest.py`, affected test files in `tests/`
- Architecture: N/A (test infrastructure consolidation)
- Implementation: Add helper functions/fixtures to `conftest.py`; update consuming test files
- Verification: Test suite produces identical pass/fail results; test coverage unchanged

## Notes

- Apply PAT-001 principle: shared helpers must make tests *more* readable, not less. If a helper obscures what is being tested, keep the duplication.
- Focus on mechanical setup (temp dirs, spec construction) rather than on test-specific mock setup (which should remain in the test file).
- Coordinate with IMP-014 (Modelica-backed fixtures) and IMP-025 (fmpy evaluation) — shared helpers should be compatible with any new fixture generation approach.
