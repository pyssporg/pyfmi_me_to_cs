# IMP-011: Add pre-compiled test fixtures to decouple end-to-end tests from vcpkg toolchain

## Evidence

- `tests/test_end_to_end.py` — full end-to-end test that requires vcpkg + SUNDIALS + CMake + C compiler
- `tests/fixtures/` — test fixture directory (contents unknown)

## Current Pain Or Risk

The end-to-end tests in `test_end_to_end.py` require a fully functional vcpkg installation with SUNDIALS, a CMake build, and a C compiler. This means:
- Tests cannot run in CI without vcpkg bootstrap (slow)
- Tests cannot run on a machine without vcpkg
- The code generation and FMU assembly steps cannot be validated independently from the build toolchain
- No mock or pre-compiled fixture allows testing the assembly/packaging layer without a real build

## Proposed Improvement

Add pre-compiled `.so` files as test fixtures so that:
1. The codegen → assembly → packaging pipeline can be tested without the CMake/vcpkg build step
2. Unit tests can validate assembly logic with known-good and known-bad fixture binaries
3. A CI-only mock build result can be used when vcpkg is unavailable

## Expected Benefit

The test suite can run in environments without vcpkg (e.g., quick linting CI, developer machines without the full toolchain). Faster test feedback: codegen tests can run in seconds instead of minutes. The assembly and packaging logic gets dedicated test coverage.

## Risk And Blast Radius

Low to Medium. Test-only changes. Pre-compiled `.so` files are platform-specific (Linux x86-64) and should be clearly documented as such. They must be kept small (trivial FMU wrappers). Risk of bit-rot if packaging format changes, but the full end-to-end test (which requires vcpkg) remains as a gate.

## Task Contract Seed

Create a minimal valid CS-FMU `.so` (trivial C function returning a constant) and check it into `tests/fixtures/`. Create test helpers that bypass the build step and call `assemble_fmu()` directly with the pre-compiled `.so`. Add tests for: correct FMU directory structure, valid `modelDescription.xml` generation, correct binary placement, and proper packaging error handling. Keep the existing `test_end_to_end.py` as the full integration gate requiring vcpkg.

## Out Of Scope

- Removing or modifying the existing end-to-end test
- Adding pre-compiled fixtures for non-Linux platforms
- Checking in large binary files
- Mocking the codegen step itself

## Traceability

- Intent: Decouple assembly/packaging tests from the build toolchain
- Product: tests/fixtures/ (new fixture files), tests/test_end_to_end.py (or new test file for assembly-only tests)
- Architecture: Test infrastructure boundary
- Implementation: Pre-compiled fixture + assembly-only test functions
- Verification: Run `pytest` without vcpkg and observe assembly tests pass; run with vcpkg and observe full end-to-end passes

## Notes

The `.so` file must be compiled for the same architecture as CI (Linux x86-64). Document in the test file that the fixture is platform-locked. Consider using `pytest.mark.skipif` to skip fixture-based tests on non-matching platforms.
