## Theme

Documentation and onboarding

## Evidence

- No `.toml` spec file in the repository root or `docs/` directory — only `pyproject.toml` exists (package metadata, not a spec example)

## Current Pain Or Risk

Users must infer the TOML spec format from the code or from the spec parser (`src/cs_fmu_packager/spec.py`). There is no self-documented example that demonstrates the [fmus], [connections], [variables], and [solver] sections together with comments explaining each field. This increases the learning curve and risks malformed spec files.

## Proposed Improvement

Add `spec.example.toml` to the repository root (or `docs/`) containing a self-documented two-FMU spec covering:
- `[fmus]` section with two FMU entries, paths, and model identifiers
- `[connections]` section showing source/target variable wiring
- `[variables]` section showing input and output variable declarations
- `[solver]` section with step size, algebraic loop max iterations, and tolerance
- Comments throughout explaining each field and valid value ranges

## Expected Benefit

Users have a working reference spec they can copy and modify. The example serves as both documentation and a test fixture. Reduces spec-related support questions.

## Risk And Blast Radius

New file only. No existing code changes. Low risk — incorrect example values would be cosmetic and correctable. The example must be syntactically valid according to `spec.py` to avoid confusion.
