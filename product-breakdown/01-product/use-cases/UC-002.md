# UC-002: Wrap A Tightly Coupled Physical Subsystem

## Actor

Simulation architect.

## Preconditions

- Several Model Exchange FMUs that interact strongly (e.g., controller-plant pairs, coupled thermal components, multi-body subsystems) exist.
- Running them as separate Co-Simulation FMUs produces poor stability or excessive communication sensitivity.

## Main Flow

1. The architect identifies the tightly coupled subsystem and collects the Model Exchange FMUs.
2. The architect creates a package specification describing the subsystem boundary, internal connections, and solver policy.
3. The packager generates one Co-Simulation FMU with a local solver.
4. The outer simulation instantiates the packaged FMU as a single component.

## Success Outcome

The subsystem has a stable Co-Simulation interface with documented local solver assumptions. Strong coupling is handled inside the wrapper.

## Primary Value

- Local integration can use smaller internal steps than the outer communication step.
- Strong coupling can be handled inside the wrapper.
- The outer simulation remains modular.
