## Current Pain Or Risk

When `MappingError: FMU 'some_fmu' not found in inspected metadata` is raised, the error message does not indicate which spec field (connection index, variable index, or FMU section) triggered the lookup. The user sees the FMU ID but not which connection or variable in their TOML spec requires debugging. The `spec.py` validator already tracks connection/variable indices for its own errors but this context is lost once the mapper processes the spec.

## Proposed Improvement

Pass the originating spec context (connection index, variable index, or FMU section) into the mapping error messages. For example:
- `"Connection 3: FMU 'some_fmu' not found in inspected metadata"`
- `"Variable 2 source: FMU 'some_fmu' not found in inspected metadata"`

## Expected Benefit

Users can immediately locate the problematic line in their TOML spec file when a mapping error occurs, rather than searching through all connections/variables manually.

## Risk And Blast Radius

Low. Changes limited to `mapper.py` error messages. No logic changes, no behavior changes, no test impacts (existing tests that check error messages may need message string updates). The `Mapper` class methods already have access to connection/variable indices via enumeration.
