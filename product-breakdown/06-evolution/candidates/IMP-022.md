## Theme

Performance optimization, code clarity

## Evidence

- `src/cs_fmu_packager/spec.py` lines 157–185 — `_parse_variable_ref()` is called up to 4 times on the same input within `_validate_variable()`
- The function is pure (no side effects, deterministic output for the same input)

## Current Pain Or Risk

- `_parse_variable_ref()` is called multiple times on the same string argument within a single function invocation, wasting CPU cycles on redundant parsing
- The repeated calls obscure the logic — a reader must verify that the calls are indeed identical and that no intermediate state changes the result

## Proposed Improvement

Cache the result of `_parse_variable_ref()` in a local variable and reuse it for all subsequent checks within `_validate_variable()`. Replace each repeated call with a reference to the cached result.

## Expected Benefit

- Minor performance improvement (avoid redundant parsing of the same string)
- Improved code clarity — the single parse result is explicit, and the function's flow becomes easier to follow

## Risk And Blast Radius

Low. The function is pure; caching its result is safe. Verify that intermediate state (e.g., `self._variables` list) is unchanged between the original call sites — if it is, caching is safe.
