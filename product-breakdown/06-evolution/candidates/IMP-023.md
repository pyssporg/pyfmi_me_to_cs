## Theme

## Evidence

- `src/cs_fmu_packager/fmu_reader.py` — contains two functions: `_find_elem()` and `_iter_elems()`
- Both functions implement the same namespace-fallback logic: try the namespaced tag first (`ns:tag`), then fall back to the plain tag
- The fallback pattern is duplicated across both functions (~8–10 lines total of identical logic)

## Current Pain Or Risk

- Duplicated XML namespace-fallback logic in two functions
- If the fallback behavior needs to change (e.g., different namespace handling, logging), both functions must be updated in sync
- A reader must inspect both functions to understand the fallback pattern

## Proposed Improvement

Extract the shared namespace-fallback logic into a helper function (e.g., `_resolve_tag()` or `_tag_with_fallback()`). Both `_find_elem()` and `_iter_elems()` call the helper instead of repeating the fallback inline.

## Expected Benefit

- Removes ~8–10 lines of duplicated logic
- Single source of truth for the namespace fallback pattern
- Easy to change or extend fallback behavior in one place

## Risk And Blast Radius

Low. Pure refactoring — no behavioral change. Verify that the extracted helper produces the same tag resolution as the inline code for all call sites. Run existing tests to confirm no regressions.
