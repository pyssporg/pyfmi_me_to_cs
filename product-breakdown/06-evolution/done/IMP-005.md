## Evidence

- `src/cs_fmu_packager/cli.py` lines 35–49: `_c_headers_dir()` probes three heuristic candidate paths and silently returns a potentially invalid fallback path

## Current Pain Or Risk

The `_c_headers_dir()` function in `cli.py` tries three hardcoded paths in order, returning the first match. If none exist, it returns a fourth path without checking its validity. This means:
- Silent fallback to an invalid path if `c_headers/` is not found
- No error message or guidance when headers cannot be located
- The heuristic breaks when the package is installed as a wheel (paths like `../../../c_headers` relative to `__file__` in a `.zip` or site-packages won't resolve)
- No CLI option to override the headers path

## Proposed Improvement

Replace the heuristic with a deterministic approach:
- Option A: Include `c_headers/` as package data in `pyproject.toml` and resolve via `importlib.resources` (or `pkg_resources` for older Python)
- Option B: Add a `--c-headers` CLI option that allows explicit override
- Raise a clear error with instructions if headers cannot be found regardless of method

## Expected Benefit

C headers are resolved deterministically regardless of install method (editable install, wheel, system package). Users can override the path when needed. Silent failures are replaced with actionable error messages.

## Risk And Blast Radius

Medium. Changes to `cli.py` and potentially `pyproject.toml` (package data declaration). If `importlib.resources` is used, minimum Python version may need to be raised (3.9+ for `importlib.resources.files`). The blast radius is limited to the header resolution step; code generation and building are unaffected.

## Task Contract Seed

In `cli.py`, replace the `_c_headers_dir()` heuristic with: (1) try `importlib.resources` to locate `c_headers` as package data, (2) add `--c-headers` CLI option, (3) fall back to checking `VCPKG_ROOT`-adjacent paths if relevant, (4) raise a clear `BuildError` with instructions if none resolve. Update `pyproject.toml` to include `c_headers/` in `[tool.setuptools.package-data]` or equivalent. Verify with `pip install .` followed by a build from a different working directory.
