## Status

Evolution

## Theme

Data model simplification, dead code removal

## Evidence

- `src/cs_fmu_packager/models.py` — `FmuMetadata` dataclass includes field `variables_by_ref: Dict[int, ScalarVariable]`
- `src/cs_fmu_packager/fmu_reader.py` — code populates `variables_by_ref` during FMU metadata parsing
- Entire source tree — `variables_by_ref` is never read or accessed by any consumer after population

## Current Pain Or Risk

- Adds unnecessary memory overhead: every `FmuMetadata` instance carries a dictionary that is never used
- Adds API surface confusion: consumers see a `variables_by_ref` field and must investigate whether it is required or expected to be populated
- Requires population code in `fmu_reader.py` that has no downstream effect, creating a false dependency

## Proposed Improvement

1. Remove the `variables_by_ref` field from the `FmuMetadata` dataclass in `models.py`
2. Remove the population code in `fmu_reader.py` that builds the `variables_by_ref` dictionary

## Expected Benefit

- Smaller memory footprint for `FmuMetadata` instances
- Simpler data model — one less field to document, test, and maintain
- Removes dead population code in `fmu_reader.py`

## Risk And Blast Radius

Low. The field is never read by any consumer. Removal is safe. Verify with a `grep` for `variables_by_ref` to ensure no downstream code references it.
