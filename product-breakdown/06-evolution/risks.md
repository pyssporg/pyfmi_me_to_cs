# Risks

| ID | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| RISK-001 | Fixed-point iteration does not converge for strongly nonlinear algebraic loops | Medium | High — blocks UC-001 (SCC packaging) for problematic systems | Make max_iterations and tolerance configurable; document convergence limitations; consider delayed-feedback fallback in future |
| RISK-002 | Internal FMU shared libraries fail to load via dlopen at runtime | Medium | High — FMU unusable | Validate internal FMU binary availability during packaging; document dlopen requirements |
| RISK-003 | SUNDIALS API changes break the solver integration | Low | Medium — requires codegen update | Pin SUNDIALS version via vcpkg baseline; capture solver version in build report |
| RISK-004 | FMI 3.0 adoption makes the FMI 2.0-only design obsolete | Low (short-term) | High (long-term) | CR-003 states design should not prevent later FMI 3.0 support; architecture separates FMI interface from solver core |
| RISK-005 | Single-platform (Linux x86_64) limits adoption | Medium | Medium — excludes Windows/macOS users | AD-006 explicitly acknowledges this as a v1 tradeoff; binaries/ directory structure supports future platform additions |
| RISK-006 | TOML spec format is not a standard simulation interchange format | Low | Low — TOML is widely supported | SPR-007 requires version-control friendliness; TOML meets this; SSP support could be added as an alternative input format later |
| RISK-007 | OMC external dependency version sensitivity | Medium | Medium — OMC-generated FMUs may change structure between versions, breaking fixture expectations or behavioral verification | Pin OMC version in CI; document tested version in test-strategy.md; regenerate fixtures after OMC upgrade and verify no regression |
| RISK-008 | OMC availability in CI | Low (Ubuntu) / Medium (macOS/Windows) | High — without OMC, fixture regeneration and verification tests are skipped | Install OMC via `apt install omc` in Linux CI; verification tests are `@pytest.mark.skipif` guarded; non-Linux users use cached fixtures |
| RISK-009 | fmpy external dependency version sensitivity | Low | Medium — fmpy API changes could break the `verify_cs_behavior()` helper | Pin `fmpy>=0.3` as minimum; document tested version; verification tests are `@pytest.mark.skipif` guarded |
| RISK-010 | Comparison tolerance maintenance | Medium | Low — tolerances set too tightly cause false failures; too loosely miss real regressions | Use `rtol=1e-4, atol=1e-6` as defaults for simple models; document tolerance rationale; make tolerances configurable via `verify_cs_behavior()` parameters |
| RISK-011 | fmpy FMI 2.0 CS compatibility | Low | Medium — fmpy may not fully support all FMI 2.0 CS features required by complex FMUs | Verification tests use simple compound models (IntegratorWithGain); document tested fmpy version; add pre-flight check in generation script |
